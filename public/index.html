Wallets

How are my keys protected?
  1. A wallet's secret key is what lets it spend, like a password. Its address is public, like an account number.
  2. This page creates the key and signs with it right here. The node only ever receives signatures, so even a hacked node can't take your key.
  3. Before the key is saved in this browser, it's encrypted with your passphrase (PBKDF2, 600,000 rounds, then AES-256-GCM). Storage only holds scrambled data, which is useless without the passphrase.
  4. Unlocking decrypts the keys into this tab's memory only. Locking, closing the tab or 15 idle minutes wipes them.
  5. There's no reset: forget the passphrase and the keys are gone. Use Back up to save an encrypted copy.
  6. It's still a learning project: a malicious browser extension running while you're unlocked could read the page's memory.

Send

What happens when I send?
  1. This page signs from | to | amount | nonce (plus the fee, if any) with your key. Only the signed transaction is sent; the key stays here. Change any of it and the signature breaks.
  2. The node checks the signature, the nonce (your transaction count, which stops replays) and that you can afford amount + fee.
  3. It waits in the mempool until the next block includes it. The fee goes to whoever adds that block.

      How do nodes stay in step?
      1. Adding a peer links both ways: this node introduces itself back.
      2. Every few seconds each node pulls its peers' chains and adopts the heaviest valid one (most work, or most stake behind it), then pulls their pending transactions.
      3. New blocks and transactions are also pushed to peers straight away. A copy that's already known fails its nonce check, so gossip never loops.
